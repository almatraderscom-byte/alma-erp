# ক্লায়েন্টের সাইট — SEO অডিট ও করণীয়

সাইটটা আমাদের নয়। **আমাদের ডাটাবেসের টুল ওখানে চলে না**, আর কোথাও লগইন করার
প্রশ্নই ওঠে না। ডেলিভারেবল একটাই — এমন একটা রিপোর্ট যা ক্লায়েন্ট নিজে বা তার
ডেভেলপার ধরে কাজ করতে পারবে।

## ধাপ

```
- [ ] ১. ডোমেইন নিশ্চিত
- [ ] ২. ক্রল
- [ ] ৩. ফল যাচাই
- [ ] ৪. করণীয় লেখো
- [ ] ৫. রিপোর্ট
```

1. **ডোমেইন** — Boss ঠিক কোন সাইট বলেছেন, নিশ্চিত হও। almatraders.com হলে এই
   skill নয়।
2. **ক্রল** — `run_website_seo_audit` → `check_website_seo_audit`। ফল হাতে আসার
   আগে কোনো সংখ্যা নয়। status `approved` মানে **এখনো ক্রল চলছে**, `executed`
   মানে হয়ে গেছে (result-এ score আর report আছে) — দুটো গুলিয়ো না। id মনে না
   থাকলে id ছাড়াই ডাকো, এই কথোপকথনের সর্বশেষ audit-ই আসবে; নতুন করে ক্রল
   চালিয়ো না।
3. **যাচাই** — বড় দাবিগুলো `fetch_website_page` দিয়ে নিজে মিলিয়ে নাও।
4. **করণীয়** — প্রতিটা সমস্যার জন্য: কোন পেজ, কী বদলাতে হবে, **কীভাবে**।
   ক্লায়েন্টের ডেভেলপার যেন ধরে কাজ করতে পারে।
5. **রিপোর্ট** — `save_artifact`। প্রাধান্য অনুযায়ী সাজানো।

## একাধিক সাইট একসাথে বললে

Boss যে ক্রমে নাম বলেছেন, সেই ক্রমেই — এবং **একটা শেষ করে তবেই পরেরটা**।
প্রতিটা সাইটের জন্য আলাদা করে: নিজের ক্রল → ফল হাতে আসা → পুরো রিপোর্ট পড়া →
ডাউনলোড লিংক। একটার ফল দিয়ে আরেকটার কথা বলবে না।

## ডেলিভারি কী, আর কী নয়

শুধু চ্যাটে লেখা = ডেলিভারি **নয়**। `save_artifact` দিয়ে ক্লায়েন্ট-রেডি একটা
ফাইল না বানানো পর্যন্ত কাজ শেষ নয়। Boss "report" শব্দটা না বললেও এটাই নিয়ম।

status `executed` হলে `check_website_seo_audit` আবার ডাকো `read: "report"` দিয়ে —
পুরো client-grade রিপোর্টটা তখন **নিজে থেকেই চ্যাটে file card হয়ে যায়**।
`read: "links"` দিলে ডাউনলোড লিংক। server নিজেই markdown, issues CSV আর live HTML
ড্যাশবোর্ড বানিয়ে রাখে — **ওগুলো আবার বানিয়ো না**।

তবু "রিপোর্ট ফাইলে আছে" বলে থেমে যেয়ো না। চ্যাটেই দিতে হবে: স্কোর, প্রতিটা
critical/high issue তার প্রমাণ ও সমাধানসহ, কোনটা আগে, আর ডাউনলোড লিংক। এই
রিপোর্ট দিয়ে Boss ক্লায়েন্টের সাথে deal করেন — পয়েন্ট বাদ দেওয়া বা ফাইল ছাড়া
"কাজ শেষ" বলা নিষেধ।

**Fix-এর পর আগে-পরে প্রমাণ:** একই সাইটে নতুন `run_website_seo_audit`, executed
হলে `read: "compare"` — স্কোর-পরিবর্তন আর সমাধান-হওয়া প্রতিটা issue প্রমাণসহ
before/after ফাইল বানায়। Boss এটাই ক্লায়েন্টকে পাঠান।

**Storage path গুলো private।** workbench-এর curl/cat দিয়ে ওগুলো পড়ার চেষ্টা
কখনো নয় — একমাত্র রাস্তা `check_website_seo_audit read:"report"`।

Boss যদি নিজের Chrome দিয়ে দেখতে বলেন, তাহলে ক্রলার দিয়ে বদলে দেওয়া নিষেধ —
মানুষের মতো সাইট-ওয়াক করতে হবে: `live_browser_act` দিয়ে HOME খোলো →
`live_browser_look` → মেনু ধরে **৫-৮টা পেজ** একে একে (home, about,
services/products, contact, blog)। প্রতিটা পেজে নোট নাও: চোখে-দেখা টাইটেল ও
হেডিং, লেআউট, ভাঙা ছবি/সেকশন, পপআপ-জ্বালা, লোডের অনুভূতি, মোবাইল-বান্ধবতা,
কনটেন্টের মান, CTA/যোগাযোগ সহজ কিনা। এগুলো রিপোর্টে **"🧑‍💻 লাইভ ব্রাউজ
পর্যবেক্ষণ"** সেকশন হয়ে যাবে, পেজ-ধরে প্রমাণসহ। সাথে `run_website_seo_audit`-ও
চালাও — দুটো মিলিয়েই পূর্ণ অডিট। ওয়াক না করে "Chrome দিয়ে করেছি" বলা, বা টুল
call না করেই "আপনার Chrome দিয়ে করছি" দাবি করা — দুটোই নিষেধ।

## যেখানে আগে আটকেছি

**খালি alt মানেই সমস্যা নয় (2026-07-26)।** সাজসজ্জার ছবি আর `aria-label` দেওয়া
বাটনের ভেতরের ছবিতে `alt=""` থাকাই সঠিক। ক্লায়েন্টকে ভুল কাজ ধরিয়ে দিলে
আমাদের বিশ্বাসযোগ্যতা যায়। সংখ্যা বলার আগে একটা পেজ নিজে দেখো।

**আমাদের টুল অন্য সাইটে চালানোর চেষ্টা।** `audit_product_seo`,
`draft_seo_fixes`, `get_website_catalog` — এগুলো almatraders.com-এর ডাটাবেসের।
এখানে তোমাকে সেগুলো দেওয়াই হয়নি; খুঁজতেও যেয়ো না।

## থামার শর্ত

- লগইন বা ক্রেডেনশিয়াল দরকার হলে → **Boss-কে বলো, নিজে চেয়ো না**
- সাইটে সরাসরি পরিবর্তন চাওয়া হলে → আমাদের সে ক্ষমতা নেই, সোজা বলো
- ডোমেইনটা আসলে আমাদের হলে → skill বদলাতে বলো
